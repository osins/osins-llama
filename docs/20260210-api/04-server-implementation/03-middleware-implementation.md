# 服务器中间件实现规范

## 中间件概述

中间件是服务器架构的重要组成部分，负责处理请求/响应周期中的通用任务，如身份验证、日志记录、速率限制等。

## 中间件类型

### 1. 认证中间件 (AuthMiddleware)

#### 功能
- 验证请求中的 API 密钥
- 支持 Bearer Token 认证
- 拒绝未授权的请求

#### 实现要求
- 继承自 Starlette 的 BaseHTTPMiddleware
- 从 Authorization 头部提取 API 密钥
- 验证密钥是否在允许列表中
- 将认证信息附加到请求状态中

#### 配置参数
- `api_keys` - 允许的 API 密钥列表

### 2. 速率限制中间件 (RateLimitMiddleware)

#### 功能
- 限制每个客户端的请求频率
- 基于 IP 地址或 API 密钥进行限制
- 返回适当的错误响应

#### 实现要求
- 使用滑动窗口算法计算请求频率
- 存储请求时间戳（可使用内存或 Redis）
- 当超过限制时返回 429 状态码

#### 配置参数
- `rate_limit_requests` - 每个时间窗口内的最大请求数
- `rate_limit_window` - 时间窗口大小（秒）

### 3. 日志记录中间件 (LoggingMiddleware)

#### 功能
- 记录请求和响应信息
- 计算请求处理时间
- 记录错误和异常

#### 实现要求
- 使用结构化日志格式
- 记录请求方法、路径、状态码
- 计算并记录响应时间
- 记录请求和响应大小

#### 记录字段
- `request_id` - 请求唯一标识
- `method` - HTTP 方法
- `path` - 请求路径
- `status_code` - 响应状态码
- `response_time` - 响应时间（毫秒）
- `user_agent` - 用户代理
- `ip_address` - 客户端 IP

## 中间件执行顺序

中间件按照添加到应用的顺序执行：

1. CORS 中间件
2. 日志记录中间件
3. 速率限制中间件
4. 认证中间件
5. 其他自定义中间件

## 中间件实现规范

### 基础要求
- 继承自 BaseHTTPMiddleware 或相应基类
- 实现异步 dispatch 方法
- 正确处理异常
- 支持配置参数

### 异常处理
- 捕获中间件内部异常
- 确保请求继续传递到下一个中间件
- 记录中间件级别的错误

### 性能考虑
- 避免在中间件中执行耗时操作
- 使用缓存优化重复计算
- 异步执行 I/O 操作

## 中间件配置

### 通过应用工厂配置
```python
def create_app(config: Config):
    app = FastAPI()
    
    # 添加中间件
    app.add_middleware(CORSMiddleware, ...)
    app.add_middleware(LoggingMiddleware, ...)
    app.add_middleware(RateLimitMiddleware, 
                      rate_limit_requests=config.security.rate_limit_requests,
                      rate_limit_window=config.security.rate_limit_window)
    app.add_middleware(AuthMiddleware, api_keys=config.security.api_keys)
    
    return app
```

### 环境变量配置
- 通过环境变量控制中间件行为
- 支持启用/禁用特定中间件
- 配置中间件参数

## 安全考虑

### 认证中间件安全
- 安全存储和比较 API 密钥
- 使用恒定时间比较防止时序攻击
- 限制密钥尝试次数

### 速率限制安全
- 防止 IP 欺骗绕过限制
- 使用可信代理头部获取真实 IP
- 实现分布式速率限制（使用 Redis）

### 日志安全
- 避免在日志中记录敏感信息
- 对日志进行适当的访问控制
- 实现日志轮转和保留策略

## 监控和调试

### 中间件指标
- 记录中间件处理的请求数
- 统计错误率和响应时间
- 监控资源使用情况

### 调试支持
- 提供详细的中间件日志
- 支持调试模式
- 记录中间件执行轨迹

## 测试策略

### 单元测试
- 测试中间件的基本功能
- 验证中间件对正常和异常请求的处理
- 检查中间件间的交互

### 集成测试
- 测试中间件与应用的集成
- 验证中间件执行顺序
- 测试错误情况下的行为

## 扩展性设计

### 插件化中间件
- 支持动态启用/禁用中间件
- 允许自定义中间件
- 提供中间件注册机制

### 配置灵活性
- 支持多种配置方式
- 提供默认配置和自定义选项
- 支持运行时配置更新

## 最佳实践

1. 保持中间件轻量级，避免复杂逻辑
2. 正确处理异常，不影响后续中间件执行
3. 使用异步操作提高性能
4. 记录适当的日志用于调试和监控
5. 实现适当的错误处理和恢复机制
6. 遵循单一职责原则，每个中间件只处理一个关注点
7. 提供清晰的配置选项
8. 对中间件进行充分的测试
