# 服务器API路由实现规范

## API路由概述

API路由是服务器的前端接口，负责接收客户端请求、验证输入、调用服务层、返回响应，确保与OpenAI API的完全兼容。

## 路由结构

### 命名空间
- 所有API端点以 `/v1` 为前缀
- 使用RESTful设计原则
- 保持与OpenAI API的一致性

### 路由分类
- `health.py` - 健康检查路由
- `completion.py` - 补全API路由
- `chat.py` - 聊天API路由
- `models.py` - 模型管理路由

## 健康检查路由

### 端点
- `GET /v1/health` - 服务健康状态检查

### 响应格式
```json
{
  "status": "healthy",
  "model_loaded": true,
  "version": "1.0.0",
  "timestamp": 1234567890
}
```

### 实现要求
- 检查模型是否已加载
- 返回服务状态信息
- 提供时间戳

## 补全API路由

### 端点
- `POST /v1/completions` - 文本补全生成

### 请求格式
- 使用 CompletionRequest 模型
- 验证所有输入参数
- 支持同步和流式响应

### 响应格式
- 同步：返回 CompletionResponse
- 流式：返回 SSE 格式的流式响应
- 错误：返回 ErrorResponse

### 实现要求
- 支持所有OpenAI兼容的参数
- 正确处理流式和非流式请求
- 准确计算和返回Token使用量
- 实现适当的错误处理

## 聊天API路由

### 端点
- `POST /v1/chat/completions` - 聊天补全生成

### 请求格式
- 使用 ChatCompletionRequest 模型
- 验证消息数组的有效性
- 支持同步和流式响应

### 响应格式
- 同步：返回 ChatCompletionResponse
- 流式：返回SSE格式的流式响应
- 错误：返回 ErrorResponse

### 实现要求
- 验证消息顺序和角色
- 支持多轮对话
- 正确处理系统、用户和助手消息
- 实现流式响应的正确格式

## 模型管理路由

### 端点
- `GET /v1/models` - 列出可用模型

### 响应格式
```json
{
  "object": "list",
  "data": [
    {
      "id": "model-name",
      "object": "model",
      "created": 1677610602,
      "owned_by": "user"
    }
  ]
}
```

### 实现要求
- 返回可用模型列表
- 包含模型元数据
- 支持分页（如需要）

## 请求处理流程

### 1. 请求接收
- 验证HTTP方法
- 解析请求体
- 验证Content-Type

### 2. 参数验证
- 使用Pydantic模型验证
- 检查必需字段
- 验证参数范围和类型

### 3. 业务逻辑
- 调用服务层方法
- 处理业务逻辑
- 管理事务（如需要）

### 4. 响应生成
- 格式化响应数据
- 设置适当的HTTP状态码
- 添加响应头

### 5. 错误处理
- 捕获并处理异常
- 返回标准化错误响应
- 记录错误日志

## 流式响应实现

### 数据块格式

### 客户端断开处理

## 错误处理

### HTTP状态码
- 200: 成功
- 400: 请求错误
- 401: 未认证
- 404: 资源未找到
- 422: 请求无法处理
- 429: 请求过多
- 500: 服务器错误

- 统一的错误响应结构

- 适当的错误代码
