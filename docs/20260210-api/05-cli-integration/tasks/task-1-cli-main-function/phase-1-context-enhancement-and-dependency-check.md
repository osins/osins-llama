2. 完善命令间的依赖检查逻辑，确保命令间的依赖关系得到正确处理，且能正确阻止未满足依赖的命令执行

### 任务 1：增强 CLIContext 类

- 实现线程安全的状态管理（使用锁或原子操作）
- 将 CLIContext 的状态管理功能集成到现有的命令中
- 输出接口：CLIContext 类，包含新增的两个方法
- 测试要求：单元测试覆盖新增方法，确保功能正确性

### 任务 2：完善依赖检查逻辑

- 输出接口：`check_command_dependencies` 函数，具备完整的依赖检查能力
- 测试要求：集成测试覆盖所有依赖组合和边界情况

## 异常类型规范

1. **CircularDependencyError**: 检测到循环依赖时抛出
   - 错误信息格式: `f"Circular dependency detected: {' -> '.join(cycle_path)}"`
   - 包含循环路径信息，便于调试

2. **UnknownCommandError**: 遇到未注册命令时抛出
   - 错误信息格式: `f"Unknown command: {command_name}"`
   - 提示用户命令不存在

3. **MissingDependencyError**: 命令执行时缺失依赖
   - 错误信息格式: `f"Command '{command_name}' cannot execute. Missing dependencies: {missing_deps}"`
   - 明确指出缺失的依赖项

## 线程安全策略

1. 使用 `threading.RLock`（可重入锁）保护 CLIContext 的状态更新操作
2. 异步命令执行时，先获取锁，检查依赖，更新状态，然后释放锁
3. 读取状态时也需要获取锁，以确保一致性
4. **锁优化**：状态检查和更新应尽量在同一个原子操作内完成，不在锁内执行命令本身，最小化锁持有时间

## 并发执行策略

1. 并发执行的命令组需先检查依赖，形成安全执行队列
2. 可用任务队列或 asyncio.gather 来控制并发执行顺序
3. 每个命令执行前都需要验证其依赖状态

## 风险评估

1. 并发访问可能导致状态不一致 - 通过使用 `threading.RLock` 可重入锁缓解
2. 循环依赖检测算法复杂度高 - 使用拓扑排序，时间复杂度 O(V+E)
3. 异常处理不当可能导致程序崩溃 - 通过规范异常类型和捕获机制缓解
4. 锁争用可能影响性能 - 在关键路径上最小化锁持有时间，状态检查和更新在同一个原子操作内完成

## 异常恢复策略

1. 当检测到异常（循环依赖、缺失依赖等）时，CLIContext 记录错误日志
2. 阻止后续依赖于当前失败命令的其他命令执行
3. 提供用户指令，说明如何纠正错误并重新执行
4. **回滚策略**：只回滚当前失败命令的状态，不回滚其依赖的后续命令状态，以保持已完成操作的完整性
5. 如有必要，提供回滚已标记为 'running' 的命令状态的机制
