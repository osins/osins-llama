# CLI 主入口函数整改 - 第二阶段：安全配置验证和日志脱敏功能增强

## 阶段目标

本阶段的目标是：
1. 增强安全配置验证，不仅检查基本字段，还要验证字段值的有效性和安全性
2. 改进日志脱敏功能，增加对更多敏感信息类型的覆盖

## 任务分解

### 任务 1：增强安全配置验证
- 扩展配置文件验证逻辑，增加对字段值的详细校验
- 添加对服务器端口和主机地址的验证
  - 端口号应在 1-65535 范围内
  - 主机地址应为有效的 IPv4、IPv6 或域名格式（支持 Unicode/ASCII 域名）
- 实现对配置文件中敏感信息的初步检测
  - 识别字段名包含 'password', 'secret', 'key', 'token', 'api_key', 'access_token', 'database_password', 'oauth_token', 'pwd', 'tok', 'auth' 等关键词及其缩写的配置项
  - 使用预定义的正则表达式模式检测常见敏感信息格式
  - 针对数据库连接字符串、第三方 API Key 等做格式验证
  - 对密码类字段验证最小长度（至少8位，默认，可通过环境变量或配置文件调整）、特殊字符（至少一个数字、一个字母、一个特殊符号，默认，可通过环境变量或配置文件调整）等要求
  - 对 JWT Token 进行基础格式验证（三个由点分隔的部分）
  - 对 OAuth Token 进行长度和格式验证
  - 支持通过配置文件或环境变量扩展敏感字段列表，包括自定义正则表达式
  - 对超大配置文件使用流式解析（如使用 ijson 库进行流式 JSON 解析），并处理流式解析中断后的状态恢复

### 任务 2：改进日志脱敏功能
- 增强脱敏功能，覆盖更多的敏感信息类型
  - API 密钥：以 'sk-' 或 'pk-' 开头的字符串，长度不少于 20 位
  - 访问令牌：JWT 格式的令牌，通常包含三个由点分隔的部分
  - 密码：在特定上下文中（如认证信息）的密码字段
  - 其他敏感信息：信用卡号、身份证号等个人身份信息
- 实现更精确的模式匹配，避免误脱敏正常信息
  - 区分字段名和上下文环境，仅对敏感字段进行脱敏
    - 对于配置键值对：只对键名包含敏感关键词的值进行脱敏
    - 对于日志文本：强制使用上下文标记机制（如日志框架标注敏感字段）作为主要判断依据，自然语义（如认证、连接、登录等关键词）作为辅助判断
  - 使用更严格的正则表达式避免误匹配
  - 按优先级匹配敏感信息，优先处理高危信息（API Key、JWT），再处理其他类型
  - 预编译常用正则表达式，避免重复编译影响性能
  - 对长日志行先进行关键词过滤，再应用正则匹配，避免不必要的复杂正则运算
  - 限制单行日志的最大处理长度（如10KB），超过长度的日志进行分段处理，确保分段后仍能拼接成完整信息用于排查问题
  - 对正则表达式设置最大匹配长度，避免超长匹配导致性能问题
  - 针对超长日志或高频日志，考虑异步脱敏处理，防止阻塞主线程
  - 实现正则匹配的缓存机制，对常见模式的匹配结果进行缓存，避免重复计算
  - 采用非回溯正则表达式，避免因复杂正则导致的性能瓶颈
  - 对超长日志行采用滑动窗口处理方式，避免一次性加载整个日志行到内存
- 确保脱敏后的信息仍然保留足够的上下文以便调试
  - 采用部分掩码（如显示首尾字符，中间用 * 替代）而非完全隐藏
  - 保留原始格式结构便于问题定位

## 实施步骤

### 步骤 1：增强配置验证函数
1. 修改 `src/llama/utils/security_utils.py` 中的 `validate_json_config` 函数
   - 添加对端口号有效性的检查（1-65535）
   - 添加对主机地址格式的验证（IPv4/IPv6/域名）
   - 添加对数据库连接字符串的格式验证
   - 添加对 JWT Token 格式的验证
   - 添加对 OAuth Token 格式的验证
   - 支持通过配置文件或环境变量扩展敏感字段列表
   - 对超大配置文件使用流式解析（如使用 ijson 库进行流式 JSON 解析）
2. 添加 `is_valid_port` 函数用于验证端口号，返回布尔值
3. 添加 `is_valid_host` 函数用于验证主机地址（支持 IPv4/IPv6/域名），返回布尔值
4. 添加 `is_valid_db_connection_string` 函数用于验证数据库连接字符串格式，返回布尔值
5. 添加 `is_valid_jwt` 函数用于验证 JWT Token 格式，返回布尔值
6. 添加 `is_valid_oauth_token` 函数用于验证 OAuth Token 格式，返回布尔值
7. 添加 `is_valid_password` 函数用于验证密码强度（至少8位，默认，可配置；包含数字、字母、特殊符号，默认，可配置），返回布尔值
8. 添加 `detect_sensitive_fields` 函数用于检测配置文件中的潜在敏感字段，返回包含敏感字段名称的列表
9. 更新 `validate_config_content` 函数以使用增强的验证逻辑
10. 在配置验证失败时：
    - 记录详细的错误信息到日志，但不暴露敏感配置内容
    - 抛出特定的安全异常（如 `SecurityValidationError`），阻止 CLI 进程继续启动，确保使用未经验证的安全配置
    - 提供清晰的错误消息指导用户修复配置问题
    - 返回特定退出码（如 1 表示配置错误）

### 步骤 2：改进日志脱敏函数
1. 修改 `src/llama/utils/cli_tools.py` 中的 `mask_sensitive` 函数
2. 添加多个预编译的非回溯正则表达式模式以匹配各种敏感信息，按优先级处理：
   - 高优先级 - API 密钥模式：`re.compile(r'\bsk-[a-zA-Z0-9]{20,}\b|\bpk-[a-zA-Z0-9]{20,}\b', re.IGNORECASE)`
   - 高优先级 - JWT 令牌模式：`re.compile(r'\beyJ[a-zA-Z0-9_]+\.eyJ[a-zA-Z0-9_]+\.[a-zA-Z0-9_-]+\b', re.IGNORECASE)`
   - 中优先级 - 通用密钥/令牌模式：`re.compile(r'\b(?:secret|key|token|password|pwd|tok|auth)\s*[:=]\s*["\']?[\w-]{10,}["\']?', re.IGNORECASE)`
   - 低优先级 - 信用卡号模式：`re.compile(r'\b(?:\d{4}[-\s]?){3}\d{4}\b', re.IGNORECASE)`
   - 低优先级 - 身份证号模式：`re.compile(r'\b\d{17}[\dXx]\b', re.IGNORECASE)`
   - 实现正则匹配结果的 LRU 缓存机制，缓存最近常用的匹配结果，避免重复计算
3. 实现上下文感知的脱敏策略：
   - 对于配置键值对：只对键名包含敏感关键词（如 password、token、key 等）的值进行脱敏
   - 对于日志文本：优先使用上下文标记机制（如日志框架标注敏感字段），其次结合自然语义（如认证、连接、登录等关键词）判断是否需要脱敏
4. 实现部分掩码策略，保留首尾字符，中间用 * 替代
5. 确保脱敏功能不影响日志的可读性
6. 在日志脱敏过程中，捕获并处理可能的异常（如正则表达式错误），确保即使脱敏失败也不会影响程序正常运行
7. 优化正则表达式性能：
   - 预编译正则表达式，避免重复编译
   - 对长日志行先进行关键词过滤，再应用正则匹配
   - 避免复杂的回溯和重复计算
   - 限制单行日志的最大处理长度（如10KB），超过长度的日志进行分段处理
   - 设置正则表达式的最大匹配长度，避免超长匹配导致性能问题
8. 在脱敏失败时记录 WARN 日志，但保证日志继续输出
9. 在 `src/llama/cli/context.py` 中为 CLIContext 的状态更新使用线程安全的 RLock 或原子操作
10. 添加 `rollback_failed_command` 方法到 CLIContext 类，用于在命令执行失败时回滚状态
    - 明确回滚操作的边界和锁粒度
    - 确保多线程/异步环境下状态的一致性
    - 提供事务性操作接口，确保 CLIContext 状态变更的原子性
11. 处理流式解析中断后的状态恢复：
    - 在配置文件流式解析过程中，如遇异常中断，确保 CLIContext 状态保持一致或安全回滚
    - 记录解析进度和状态，便于恢复或诊断
    - 实现解析过程的检查点机制，定期保存 CLIContext 的状态快照，允许从中断点继续解析或回滚到上一安全状态
    - 状态快照采用深拷贝方式，确保快照数据的独立性和一致性
    - 实现增量状态更新机制，仅记录自上次快照以来的变化，减少内存开销
12. 实现异步日志脱敏处理机制：
    - 为高频日志或超长日志提供异步脱敏处理选项，防止阻塞主线程
    - 确保异步处理中的线程安全和数据一致性
    - 在异步脱敏失败时提供同步降级处理
